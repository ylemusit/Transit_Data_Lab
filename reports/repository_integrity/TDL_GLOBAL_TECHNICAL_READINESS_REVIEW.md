## Áreas sospechosas: clasificación específica

- **Compliance SQL:** sigue activo porque el gate actual ejecuta el SQL Phase 2. Los tres literales de metadata histórica deben preservarse; los diez `read_blob` jurídicos exigen una ruta nueva portable con comparación de hash de los archivos del checkout. El gate pasó aquí porque existe la ruta original absoluta. Su PASS no prueba portabilidad.
- **Bases:** ubicación codificada desde `ROOT`; falta de DB provoca fallo, nunca PASS. El error inicial de `unittest` nombró la ruta ausente; el gate `sha(DB)` no ofrece un preflight claro. Se verificaron SHA antes y después de los gates; los enlaces temporales apuntaron a las bases protegidas, sin copiar bytes ni alterar hashes.
- **`main.stops`:** coincidencia de contenido comprobada; no se halló consumidor productivo fuera del sentinel histórico, ni justificación de su creación. Decisión humana requerida para eliminación/migración.
- **Reglas/finding:** `audit_contract.py` define estados y severidades, exige `rule_id`, tabla, locator y hash de fuente para identidad estable. No exige evidencia rica para todo futuro finding en estado DETECTED; la política de transición humana sí exige reviewer/evidencia en estados de revisión. La extensibilidad y versión por regla faltan.
- **Dataset desconocido:** el pipeline acepta un ZIP GTFS genérico sin código por operador dentro del catálogo soportado; el fixture sintético completo y los tests pasaron. Tablas fuera del catálogo se inventarían como `NOT_SUPPORTED`; no hay prueba de todos los formatos/escala real. Se preserva la distinción `INGESTION_ERROR`/`INSPECTION_ERROR`/`FAIL_TECHNICAL`/`NOT_EVALUABLE` en JSON, aunque faltan códigos de recursos/configuración más finos.
- **Portabilidad:** Python/pathlib y salidas UTF-8 favorecen portabilidad; los scripts PowerShell son `WINDOWS_DEPENDENT`; SQL congelado es `BROKEN` para checkout nuevo independiente; gates sintéticos son `PORTABLE_WITH_REQUIREMENTS` (Python 3.12, DuckDB CLI, lxml en Compliance); Linux/macOS global `NOT_VERIFIED`. El incidente LF/CRLF del replay histórico ya tiene serialización byte-a-byte y gate PASS; no es defecto nuevo.
- **Backup:** `PARTIAL`: inventario, hashes selectivos y pasos propuestos sí; copia integral y restore probado no acreditados. No se hizo backup ni se copiaron archivos grandes.
- **Desktop:** la deuda del producto es independiente. La antigua advertencia de 20 cambios locales ya no describe el checkout observado; `PROJECT_STATUS.md` se actualizó. No se inspeccionó funcionalidad Desktop ni se modificó su repositorio.
